# nasa-space-biology-knowledge-engine
AI-powered knowledge engine for exploring, searching, and understanding NASA space biology research using RAG and semantic search.

## MVP (`mvp-core` branch): semantic search over 20 papers

This branch is the **retrieval part** of the RAG pipeline. You ask a question in plain English and it returns the most relevant passages from a set of NASA space biology papers, each with a link to its paper. There is no LLM yet. The search is the foundation that answer generation will be built on later.

It currently works on **20 sample papers** (listed in `papers.txt`), picked from the 607 publications in `raw_data/SB_publication_PMC.csv`.

### How it works

```
papers.txt ──► fetch_papers.py ──► data/raw/<PMCID>.json ──► build_index.py ──► data/index.faiss ──► search.py
 (PMC IDs)     download full text   (one file per paper)     clean, chunk,      data/chunks.jsonl    ask a question,
               from NCBI                                     embed               (search index)      get top passages
```

**Step 1: Download papers (`fetch_papers.py`)**
- Reads the PMC IDs in `papers.txt` (e.g. `PMC3630201`).
- Downloads each paper's full text from NCBI's [BioC API](https://www.ncbi.nlm.nih.gov/research/bionlp/APIs/BioC-PMC/) as structured JSON split into sections (abstract, intro, methods and so on).
- Saves each one to `data/raw/<PMCID>.json`. Papers that are already downloaded are skipped, so it's safe to re-run.

**Step 2: Build the search index (`build_index.py`)**
1. **Clean:** removes citation markers like `[3]` or `[4-6]` and extra whitespace.
2. **Filter:** keeps the useful sections (abstract, introduction, methods, results, discussion, conclusion, figure captions) and drops references, acknowledgments, author info and so on.
3. **Chunk:** splits each section into pieces of **250 words** that overlap by **50 words**, so a sentence cut at a boundary still appears whole in the next chunk. Each chunk records its paper ID, title, URL, section and heading.
4. **Embed:** turns each chunk (heading + text) into a vector with the [`all-MiniLM-L6-v2`](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2) sentence-transformer model. Texts with similar meaning get similar vectors. The paper title is left out on purpose, because putting it in every chunk biases results toward papers whose title happens to match the question.
5. **Index:** stores the vectors in a [FAISS](https://github.com/facebookresearch/faiss) index (`data/index.faiss`) and the chunk text and metadata in `data/chunks.jsonl`. Line *i* of the JSONL file belongs to vector *i* in the index.

**Step 3: Search (`search.py`)**
- Embeds your question with the same model.
- Finds the `k` chunks whose vectors are closest to it (cosine similarity, so a higher score means more relevant).
- Prints each result with its score, paper ID, section, title, link and a text preview.
- With `--eval`, it runs the test questions in `eval_queries.txt` and checks whether the expected papers show up in the top results.

### Files

| File | What it is |
|---|---|
| `papers.txt` | The 20 PMC IDs to use. Add or remove IDs here (one per line, `#` for comments). |
| `fetch_papers.py` | Step 1: downloads papers into `data/raw/` |
| `build_index.py` | Step 2: cleans, chunks and embeds them, then builds the index |
| `search.py` | Step 3: searches the index from the terminal |
| `eval_queries.txt` | Test questions and the papers each should find (`question \| PMC IDs`) |
| `requirements.txt` | Python dependencies |
| `raw_data/SB_publication_PMC.csv` | Full list of 607 NASA space biology publications (title + link) |
| `data/` | Generated by the scripts and **not committed to git** (in `.gitignore`). Rebuild it with steps 1-2. |

## Running it in the terminal

### Prerequisites
- Python 3.9 or newer (`python3 --version`)
- Git
- An internet connection: the papers and the embedding model (about 90 MB, downloaded automatically on first use) are fetched online

### 1. Get the code on the `mvp-core` branch

```bash
git clone <repo-url>
cd nasa-space-biology-knowledge-engine
git switch mvp-core
```

If you already have the repo:

```bash
git fetch
git switch mvp-core      # creates a local branch that tracks origin/mvp-core
git pull
```

> **Don't see the new files?** Check `git status`. If it says `On branch mvp-core` but the branch has no upstream and the files are missing, your local branch was created from `master` instead of from the remote one. Fix it with:
> ```bash
> git merge --ff-only origin/mvp-core
> git branch --set-upstream-to=origin/mvp-core
> ```

### 2. Create a virtual environment and install dependencies

macOS / Linux:
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
```

Windows (PowerShell):
```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install --upgrade pip
pip install -r requirements.txt
```

This installs `sentence-transformers` (which pulls in PyTorch, so it takes a few minutes), `faiss-cpu` and `numpy`. Run `source .venv/bin/activate` (or the Windows equivalent) again whenever you open a new terminal.

### 3. Download the papers

```bash
python fetch_papers.py
```

FETCH_OUTPUT

> **Seeing `HTTP Error 429: Too Many Requests`?** NCBI limits how fast you can download. Wait a minute and run `python fetch_papers.py` again. Papers already downloaded show as `cached` and are skipped, so each run picks up where the last one stopped. Repeat until it says `20/20`.

### 4. Build the search index

```bash
python build_index.py
```

BUILD_OUTPUT

The first run downloads the embedding model. Re-run this step whenever you change `papers.txt` or the chunking code.

### 5. Search

```bash
python search.py "How does microgravity affect skeletal muscle?"
```

SEARCH_OUTPUT

Options:

```bash
python search.py "What causes bone loss in microgravity?" -k 10   # return 10 results instead of 5
python search.py --eval                                            # run the test questions in eval_queries.txt
python search.py --help
```

`--eval` prints the results for each test question, then a `HIT` or `MISS` line and a final score:

EVAL_OUTPUT

### Quick start (all commands)

```bash
git switch mvp-core
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python fetch_papers.py          # re-run if some papers fail with HTTP 429
python build_index.py
python search.py "How do plant roots sense gravity?"
python search.py --eval
```

## Common changes

- **Use different papers:** edit `papers.txt` (copy PMC IDs from the links in `raw_data/SB_publication_PMC.csv`), then run `fetch_papers.py` and `build_index.py` again. Some papers aren't in the PMC open-access set; those fail with `not in the PMC open-access text set; pick another paper`.
- **Add a test question:** add a line to `eval_queries.txt` in the form `question | PMC1234, PMC5678`, then run `python search.py --eval`.
- **Change chunk size or model:** edit `CHUNK_WORDS` / `OVERLAP_WORDS` / `MODEL_NAME` in `build_index.py`, then rebuild. If you change `MODEL_NAME`, change it in `search.py` too; the two must match.

## Troubleshooting

| Problem | Fix |
|---|---|
| `HTTP Error 429: Too Many Requests` | NCBI rate limit. Wait a minute and re-run `fetch_papers.py`. |
| `data/index.faiss not found. Run build_index.py first.` | Run steps 3 and 4 before searching. |
| `No papers in data/raw. Run fetch_papers.py first.` | Run step 3. |
| `<PMCID>: missing, run fetch_papers.py (skipped)` | That paper failed to download. Re-run `fetch_papers.py`, then `build_index.py`. |
| `ModuleNotFoundError: No module named 'faiss'` (or `sentence_transformers`) | The virtual environment isn't active. Run `source .venv/bin/activate`, or install with `pip install -r requirements.txt`. |
| `NotOpenSSLWarning: urllib3 v2 only supports OpenSSL 1.1.1+` | Harmless warning on macOS's built-in Python. It can be ignored. |
